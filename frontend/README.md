## 啟動與驗證

需 Node.js 24 LTS。執行 `npm ci`、`npm run dev`；正式輸出使用 `npm run build`，單元測試使用 `npm test`。

瀏覽器測試需先啟動 dev server、安裝 Playwright Chromium（`npx playwright install chromium`），再執行：

```sh
npm run test:browser
npm run test:browser:v2
npm run test:browser:public
npm run test:browser:ux
npm run test:browser:enhancements
npm run test:browser:all
```

有系統 Chromium 可加 `CHROMIUM_PATH=/usr/bin/chromium`，`BASE_URL` 可指定網址。截圖位於 docs/previews/。

## 操作方式

以下為管理工作區（`#/demo`）的體驗方式。

- 頂部可切換會員、社團、地區與平台示範身分；這是展示控制，不是真實授權。
- 登出可體驗登入、註冊、忘記密碼與補件。所有帳號固定使用示範密碼 `DemoPass2026!`；密碼不保存，重設亦不會改變此示範值。
- 帳號設定可單項變更電話／Email、修改一次帳號代號、設定頭像；個人資料可調整姓名、call name、隱私。
- 社團管理、角色與交接、年度確認、入社、三段轉社、退社／OB、歷史同意、支援案件與異動紀錄均有假資料互動。
- 地區管理可新增／停復用社團與示範雙地區核准跨區。新增社團會出現在入社、名冊及管理者情境中。
- 名冊可搜尋、篩選、排序與分頁；可載入分頁示範資料。畫面情境可檢視載入、離線、衝突、無權限與登入逾時。
- 所有資料只存在記憶體；重新整理或重設示範資料即還原。業務日固定 2026-10-15；年度頁可模擬年度邊界。

## 通用頁面顯示與隱私（2026-10-15 已確認）

未登入訪客可瀏覽商家地圖、社團行事曆；會員資料查詢與商家優惠兌換須登入後才可使用。優惠兌換的功能範圍、階段及流程另議，不因入口規則而列為第一階段交付。

會員電話預設隱藏、會員 Email 預設開啟，兩者皆可由本人以 checkbox 調整。會員資料查詢仍須登入，預設開啟不代表匿名 API 可取得會員私人欄位；授權管理者備查範圍另定。

商家地圖呈現扶輪 call name、公司名稱、所屬社團名稱與公司聯絡方式；本階段暫不顯示本人姓名，後續可依需求調整；未填 call name 時提示本人補填，不自動以姓名替代。公司聯絡方式包含公司電話、公司 Email、網站與營業地址，獨立填寫，不自動帶入會員私人聯絡資料；必填及個別欄位顯示規則另定。

會員須經社團管理者核准入社才取得被查詢及公司地圖顯示資格。沒有任何有效社籍時，預設會員查詢排除該會員，但登入使用者可勾選特殊選項查詢已退出、OB 等非正常社籍會員，仍套用欄位隱私；商家地圖以當年度社籍為免費資格，非當年度社友可付費以廣告形式曝光，不設年資門檻；付費曝光自平台管理者設定起始日起一年，到期未續費則下架地圖並保留資料；保留本人資料與歷史，多會員共用公司規則另議。

## 入社申請退回與撤回（2026-10-15 已確認）

- 社團管理者拒絕入社申請時須填寫原因，本人可查看。
- 本人可依原因修改資料後重新申請；重新申請仍須由該社團管理者核准，不自動取得社籍。
- 核准前本人可自行撤回申請；撤回不得建立有效社籍或取得查詢／地圖曝光資格。
- 申請歷史保存方式、重送限制及核准與撤回同時發生的處理另定；社籍日期與待審申請上限見下方已確認規則。

## 入社審核、日期與申請數量（2026-10-15 已確認）

- 該社團管理者可查看申請人的姓名、call name 與入社說明；電話與 Email 依本人隱私設定顯示。此審核權不延伸至其他社團或其他私人欄位。
- 社籍生效日期預設核准當日，允許填寫實際入社日期，以支援既有社員加入系統。審核畫面由誰填寫／調整日期、日期可用範圍與歷史衝突處理仍待細化；回填日期不代表核准前即有顯示或存取資格。
- 同一會員、同一社團類型一次僅可有一筆待審入社申請；扶青社與扶輪社可分別申請，未核定的新類型不因此啟用。
- 已有同類型有效社籍時，須走轉社流程，不得以一般入社申請建立第二筆有效社籍；轉社由本人提出、原社團與目標社團管理者雙方核准；詳見下方已確認流程。
- 實作時由伺服器及儲存層處理同時送出／核准的競爭，維持申請與社籍上限；本文件僅記錄規格，尚未實作或驗收。

## 轉社、退社與 OB（2026-10-15 已確認）

- 轉社由會員本人提出並選擇目標社團；管理者代辦是否開放留待後續討論。
- 原社團與目標社團管理者雙方同意後，會員本人最終確認執行才完成轉社；各自僅審核自己社團的一側，不因申請而取得對方社團管理權。
- 等待審核及本人確認期間保留原社籍；雙方核准且本人最終確認執行成功時，才以同一受控操作結束原社籍、新增目標社籍，保留歷史且遵守同類型有效社籍上限。
- 退社／畢業可由本人提出，由所屬社團管理者確認；所屬社團管理者也可直接辦理，但須填寫原因並保留異動紀錄。
- 扶青社畢業稱為「OB」。OB 與退社分開記錄原因；是否仍有社團資格、會員查詢／地圖曝光資格或其他權益，尚待確認，不從名稱推定。
- 轉社拒絕、撤回、逾期、核准與異動競爭、實際生效日期及 OB 的資料狀態另行細化。

## 三段式轉社與生效（2026-10-15 最新確認）

1. 會員本人提出轉社申請。
2. 原社團與目標社團管理者各自回覆核准。
3. 雙方核准後，由會員本人最終確認執行，才生效；雙方核准本身不得自動切換社籍。

生效日期預設本人最終確認且執行成功當日，原社籍結束與新社籍開始同步完成；此規則取代先前「雙方核准當日」提案。等待全程保留原社籍。任一方拒絕即結束申請並須填原因；本人完成前可撤回，原社籍保留。核准、拒絕、撤回與最終執行須檢查狀態，已完成後不可當作待審撤回；詳細狀態與衝突處理待定。

## 地圖免費資格與廣告曝光（2026-10-15 最新決策）

- 當年度正常會員持有社籍，地圖曝光不用付費；非當年度社友想曝光商家，採付費會員的廣告形式。取消先前同社團社籍年資門檻。
- 付費廣告保留社團圖標、以不同顏色呈現，並加「廣告」文字標示。
- 平台管理者設定曝光起始日，結束日為起始日加一年；到期續費並確認商家資料，未續費則退出地圖並保留資料。日期邊界、時區與閏日處理待細化。
- 此處僅確認平台管理者設定曝光日期的動作，不推導其他平台維運權限。收款與對帳方式、廣告費用、續費及共用公司資格仍待定，不代表本階段串接金流。
- 扶輪年度為 7/1 至隔年 6/30；各社管理帳號及當年度社長、秘書可在面板確認社員狀態。年度確認流程與轉社／退社當年度的曝光處理待確認。

- 社長、秘書或該社團管理帳號任一方核准，即代表該社團同意，不要求社長與秘書重複核准。
- 轉社仍須原社團、目標社團分別核准，再由會員本人最終確認執行才生效；同社多人操作不得重複建立核准或社籍。

- 角色可選清單、授予與撤銷的即時生效規則、避免無管理者的處理及審核衝突細節仍待定。

## 電話、帳號代號與密碼復原（2026-10-15 已確認）

- 電話可用於登入，同一電話只能綁定一個帳號；以含國碼的格式儲存，支援國際使用。電話仍為選填，未填不占唯一值；具體國碼正規化與格式驗證待定稿。

- 忘記密碼採寄送一次性、限時有效的重設連結到已登錄 Email；成功後撤銷該復原憑證與既有登入狀態。有效期限已確認為 30 分鐘、單次使用，重送使舊連結失效；頻率限制另定。

## 本地 API 串接模式

預設仍為公開首頁與合成資料展示；`VITE_API_MODE=live` 才會把登入後服務切換到真實後端。公開首頁、地圖、行事曆仍為合成展示資料。本模式提供註冊、登入／登出、入社申請、授權社團核准、會員名冊與隱私詳情，以及「我的帳號」姓名／call name、聯絡隱私、電話／Email 單項密碼驗證變更及一次性會員代號變更，其餘管理功能保留於預設展示模式。

先依 `backend/README.md` 啟動 PostgreSQL 與 API，並準備本地 HTTPS 憑證（只供本地使用，不提交私鑰），再啟動：

```sh
VITE_API_MODE=live DEV_TLS_KEY=/absolute/local/key.pem DEV_TLS_CERT=/absolute/local/cert.pem npm run dev
```

開啟 `https://localhost:5173/`。Vite 同源代理 `/api` 到 `http://localhost:8080`（可用 `DEV_API_TARGET` 調整）。後端需允許該 HTTPS Origin。必須使用 HTTPS，維持 `__Host-session` Secure／HttpOnly cookie。自簽憑證只用於本地；正式環境須使用受信任憑證與同源反向代理，不能直接使用 Vite 開發伺服器。

CSRF token 僅在記憶體保存；登入、角色與社團範圍皆由伺服器提供，沒有展示角色切換。資料不寫入 localStorage。新增操作在結果未知時，會以記憶體中的 SHA-256 輸入指紋重用 Idempotency-Key；輸入變更會換新 key，成功或登出後清除，不額外保存密碼明文。更新後會重新讀取 `/me`；API 錯誤保留 requestId 以供查詢。「我的帳號」非密碼草稿僅留於記憶體；切換頁籤、返回公開頁與登出前會確認未儲存修改，重新整理／關頁使用瀏覽器原生提醒。密碼每次操作完成（含失敗）清空；409 不自動重送或覆蓋，須明確重新讀取並確認捨棄草稿後再操作。其他原有串接表單尚未提供離頁提醒。

真實端到端檢查（會建立 `.test` 合成帳號與入社資料，只用獨立本地測試資料庫）：

```sh
BASE_URL=https://localhost:5173/ CHROMIUM_PATH=/usr/bin/chromium \
LIVE_REVIEWER_EMAIL='<local seeded reviewer>' LIVE_REVIEWER_PASSWORD='<local password>' \
LIVE_CLUB_ID='<reviewer club UUID>' npm run test:browser:live
```

未設定 `CHROMIUM_PATH` 時使用 Playwright 安裝的瀏覽器，適用 CI；本地可指定系統 Chromium。

測試只對本地自簽 HTTPS 使用 `ignoreHTTPSErrors`，不模擬 API 回應；包括註冊、入社前名冊隱藏、登入、入社、審核、名冊及私人電話省略、360px 無橫向溢出。現有其他瀏覽器測試仍應在預設 mock 模式執行。

帳號串接驗證（同樣只用獨立本地測試資料庫）：

```sh
BASE_URL=https://localhost:5173/ CHROMIUM_PATH=/usr/bin/chromium npm run test:browser:live:account
```

此流程建立隨機 `.test` 帳號，驗證資料／隱私保存、草稿離頁取消、錯密碼保留登入、Email／電話變更後 Session 輪替與新識別登入、舊 Email／代號失效、一次性代號限制及 360px 版面。聯絡方式仍採目前密碼驗證；電話／信箱驗證碼保留後續可選整合，並未在本次加入。頭像因尚無資產服務不提供上傳。
