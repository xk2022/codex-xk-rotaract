# 前端操作雛形

React 19 + TypeScript 5 + Vite 7 + Tailwind 4。本地合成資料雛形，沒有後端驗證、永久保存或真實帳號；重新整理或「重設示範資料」會回到初始狀態。品牌與版面依[需求基準 B08](../docs/2027/13-requirements-baseline.md#b08-ui-與前端)製作自有元件，未使用未取得授權的 Metronic 模板。

## 啟動與驗證

需 Node.js 24 LTS、npm；版本由 package-lock.json 鎖定。

```sh
cd frontend
npm ci
npm run dev
```

預設開啟本機 http://localhost:5173；遠端工作區需平台提供連接埠轉送，不能把遠端 loopback 當成本機已可存取。

```sh
npm run build
npm test
```

瀏覽器驗證需先在另一個終端啟動 dev server，再執行：

```sh
npx playwright install chromium
npm run test:browser
```

若系統已提供 Chromium，可不下載，改用 `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`；`BASE_URL` 可指定測試網址。測試截圖寫入 docs/previews/。正式建置輸出在 frontend/dist，未發布。

## 通用頁面顯示與隱私（2026-10-15 已確認）

未登入訪客可瀏覽商家地圖、社團行事曆；會員資料查詢與商家優惠兌換須登入後才可使用。優惠兌換的功能範圍、階段及流程另議，不因入口規則而列為第一階段交付。

會員須經社團管理者核准入社才取得被查詢及公司地圖顯示資格。沒有任何有效社籍時，預設會員查詢排除該會員，但登入使用者可勾選特殊選項查詢已退出、OB 等非正常社籍會員，仍套用欄位隱私；商家地圖以當年度社籍為免費資格，非當年度社友可付費以廣告形式曝光，不設年資門檻；付費曝光自平台管理者設定起始日起一年，到期未續費則下架地圖並保留資料；保留本人資料與歷史，多會員共用公司規則另議。

## 入社申請退回與撤回（2026-10-15 已確認）

- 社團管理者拒絕入社申請時須填寫原因，本人可查看。
- 本人可依原因修改資料後重新申請；重新申請仍須由該社團管理者核准，不自動取得社籍。
- 核准前本人可自行撤回申請；撤回不得建立有效社籍或取得查詢／地圖曝光資格。
- 申請歷史保存方式、重送限制及核准與撤回同時發生的處理另定；社籍日期與待審申請上限見下方已確認規則。

## 入社審核、日期與申請數量（2026-10-15 已確認）

- 該社團管理者可查看申請人的姓名、call name 與入社說明；電話與 Email 依本人隱私設定顯示。此審核權不延伸至其他社團或其他私人欄位。
- 社籍生效日期預設核准當日，允許填寫實際入社日期，以支援既有社員加入系統。審核畫面由誰填寫／調整日期、日期可用範圍與歷史衝突處理仍待細化；回填日期不代表核准前即有顯示或存取資格。
- 同一會員、同一社團類型一次僅可有一筆待審入社申請；扶青社與扶輪社可分別申請，未核定的新類型不因此啟用。
- 已有同類型有效社籍時，須走轉社流程，不得以一般入社申請建立第二筆有效社籍；轉社由本人提出、原社團與目標社團管理者雙方核准；詳見下方已確認流程。
- 實作時由伺服器及儲存層處理同時送出／核准的競爭，維持申請與社籍上限；本文件僅記錄規格，尚未實作或驗收。

## 轉社、退社與 OB（2026-10-15 已確認）

- 轉社由會員本人提出並選擇目標社團；管理者代辦是否開放留待後續討論。
- 原社團與目標社團管理者雙方同意後，會員本人最終確認執行才完成轉社；各自僅審核自己社團的一側，不因申請而取得對方社團管理權。
- 等待審核及本人確認期間保留原社籍；雙方核准且本人最終確認執行成功時，才以同一受控操作結束原社籍、新增目標社籍，保留歷史且遵守同類型有效社籍上限。
- 退社／畢業可由本人提出，由所屬社團管理者確認；所屬社團管理者也可直接辦理，但須填寫原因並保留異動紀錄。
- 扶青社畢業稱為「OB」。OB 與退社分開記錄原因；是否仍有社團資格、會員查詢／地圖曝光資格或其他權益，尚待確認，不從名稱推定。
- 轉社拒絕、撤回、逾期、核准與異動競爭、實際生效日期及 OB 的資料狀態另行細化。

## 三段式轉社與生效（2026-10-15 最新確認）

1. 會員本人提出轉社申請。
2. 原社團與目標社團管理者各自回覆核准。
3. 雙方核准後，由會員本人最終確認執行，才生效；雙方核准本身不得自動切換社籍。

生效日期預設本人最終確認且執行成功當日，原社籍結束與新社籍開始同步完成；此規則取代先前「雙方核准當日」提案。等待全程保留原社籍。任一方拒絕即結束申請並須填原因；本人完成前可撤回，原社籍保留。核准、拒絕、撤回與最終執行須檢查狀態，已完成後不可當作待審撤回；詳細狀態與衝突處理待定。

## 地圖免費資格與廣告曝光（2026-10-15 最新決策）

- 當年度正常會員持有社籍，地圖曝光不用付費；非當年度社友想曝光商家，採付費會員的廣告形式。取消先前同社團社籍年資門檻。
- 付費廣告保留社團圖標、以不同顏色呈現，並加「廣告」文字標示。
- 平台管理者設定曝光起始日，結束日為起始日加一年；到期續費並確認商家資料，未續費則退出地圖並保留資料。日期邊界、時區與閏日處理待細化。
- 此處僅確認平台管理者設定曝光日期的動作，不推導其他平台維運權限。收款與對帳方式、廣告費用、續費及共用公司資格仍待定，不代表本階段串接金流。
- 扶輪年度為 7/1 至隔年 6/30；各社管理帳號及當年度社長、秘書可在面板確認社員狀態。年度確認流程與轉社／退社當年度的曝光處理待確認。

## GitHub Pages 部署

`.github/workflows/deploy-frontend.yml` 在 main 的前端變更或手動執行時，使用 Node 24、npm ci、單元測試、TypeScript／Vite 建置，僅將 frontend/dist 部署至 Pages。相對資產路徑支援儲存庫子路徑與自訂網域；不發布規格文件、OpenAPI或測試截圖。

部署網址以 GitHub Actions 的 github-pages environment 輸出為準。預期專案路徑為 `https://xk2022.github.io/codex-xk-rotaract/`，首次部署成功前不視為已上線。

私人儲存庫需 GitHub 方案支援 Pages；儲存庫保留 private。工作流程嘗試使用目前授權啟用 Pages，若平台拒絕自動啟用，管理者需在 Settings → Pages 將 Source 設為 GitHub Actions，再重跑工作流程。不要為了部署直接將儲存庫改為公開。

Pages 僅提供前端靜態雛形，沒有真實登入／密碼驗證或永久保存；請只填合成資料。網址中的頁面切換不使用伺服器路由，不需要 SPA 404 重導。
