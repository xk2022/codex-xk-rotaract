# 開發階段順序與討論清單

狀態：已確認先會員／社團資料與權限，再活動行事曆；舊資料先盤點與清理後分批移轉。其餘階段為提案；目前只做第 0 階段文件。不估工期、不啟動程式開發。

## 建議階段與進出條件

| 階段 | 目的與候選範圍 | 前提 | 完成判定 |
| --- | --- | --- | --- |
| 0 規格對齊（現在） | 舊版分析、功能規格、角色矩陣、公開政策、MVP 與移轉決策 | 舊原始碼可讀 | 使用者確認第一條流程與排除項目；關键未決規則有紀錄 |
| 1 基礎與第一條管理流程 | AUTH + ORG + 最小 MEM（類型、社籍子表、上限、歷史及公開同意）；以合成資料製作可點擊雛形、API 契約，確認後才實作 | 階段 0 核定、技術與環境選型 | 管理者登入，僅可維護自己的社團與會員；復原與跨範圍拒絕驗收通過 |
| 2 活動發布與公開瀏覽 | EVT + 最小 WEB；社團活動草稿到公開行事曆 | 組織與權限穩定 | 發布／修改／取消、日期邊界、私有活動與授權驗證完整 |
| 3 職業交流 | BIZ，再 MAP；先列表與详情，地图為可選後續 | 公司維護角色與公開規則確認 | 公司分類、會員關聯、公開資料與地图失败替代流程驗收 |
| 4 企業申請／繳費與後台補強 | PAY 語意確認後實作；按需要加入字典、稽核查詢與匯出 | 登錄用途、週期、權限確認 | 防重送、作廢、更正與稽核符合規則；不混入未定金流 |
| 5 移轉、試用與上線 | 分批移轉、業務驗收、備份還原、切換與回退 | 所需功能验收、資料授權與部署决定 | 對帳與關聯核對通過、回復演練成功、使用者核準上線 |

資料盤點可從階段 0 並行；試轉可在對應模組穩定後進行。正式資料切換與上線另需明確授權。階段 1、2 的優先順序與分批移轉方向已確認；各階段功能細節、後續順序與切換仍待核定，不代表已授權開發或部署。

## 為何建議這個順序

地區／社團決定會員、活動、公司關聯及授權範圍；舊版不能只靠選單判斷 API 權限，應優先定義與驗收。活動流程能用較少模組驗證從管理到公開查詢的完整價值。公司地图依赖分類、資料公開與有效座標；企業 Pay 記錄的業務語意仍不清，晚于名錄確認較合适。

依此次答覆，先以會員／社團資料與權限作為第一階段，再安排活動行事曆；公司名錄與地圖維持後續提案。

### 保留到後續討論：平台與較高權限角色

依使用者最新說明，會員使用角色（含地區／社團管理者）與平台管理、團隊維運權限需分開考量；目前無法定義「較高權限管理者」，本組議題留待後續討論，不要求現在定義。

- 【歷史未決】 定義「較高權限管理者」包含哪些角色，及可操作的資料範圍。
- 【歷史未決】 定義平台管理者與協助平台維運的團隊角色，各自需要哪些權限。
- 【歷史未決】 定義 admin 例外身分、授予／撤銷方式及稽核要求；不自動視所有平台管理者為 admin。
- 【歷史未決】 確認上述角色與歷史隱藏、公開請求及例外公開操作的對應。

可先討論一般會員與社團／地區管理流程；涉及上述特殊權限的功能，須在角色核定後才能定稿與驗收。
