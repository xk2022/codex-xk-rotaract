## 帳號流程的保存規則

1. 基本資料、登入聯絡資料與代號各有清楚的分頁，只有當前分頁的表單可互動。
2. 非密碼草稿在切換分頁後保留，分頁與整體畫面標示有未儲存變更；可明確放棄。
3. 密碼不作長期草稿，切換分頁時清除；單項聯絡資料變更仍須當次密碼驗證。
4. 頭像上傳後僅準備預覽，與姓名／call name 一起按「儲存基本資料」才套用；未存即離開的內容受草稿確認保護。
5. 離頁或切換範圍時，取消確認應留在原頁及原身分；確認捨棄才前往新位置。
6. 重新整理仍會還原全部合成資料，未加入 localStorage 或跨裝置草稿，也不保存密碼。

## 深連結與角色回退

來源：[portalRoute.ts](../../frontend/src/portalRoute.ts)。

| 情境 | 預期行為 |
| --- | --- |
| `#/demo?view=annual` | 進入明示的管理假資料模式並顯示年度名冊 |
| 已登入時切換 `#/workspace?view=account` | 進帳號設定；未存變更先確認 |
| 未登入直達 `#/workspace?view=account` | 顯示登入入口；內頁 URL 不建立 Session |
| 會員嘗試管理角色頁 `view=roles` | 回退至該身分允許的頁面，不增加管理權 |
| 未知 `view` | 回到總覽，再依角色可用頁面處理 |
| 公開站／瀏覽器返回前進 | 依 hash 切換入口；有受保護草稿時可取消離開 |

`view` 是 hash 內的查詢參數，不是伺服器路徑。會員詳情、搜尋條件及私人資料沒有因此取得獨立分享網址。本輪深連結只涵蓋既有工作區頁面。

## 視覺與互動基準

共用 CSS 新增 `--text-primary: #253049`、`--text-secondary: #596579`、`--surface: #fff`、`--control-height: 44px`、`--focus-ring: #9c0c27`，根字級調為 15px。輸入元件 16px、主要按鈕 14px、主要導覽至少 46px 高；公開站與工作區的小字同步改善。這些是目前的實作基準，仍需檢查個別元件覆寫及完整頁面實際呈現。

延續品牌紅及公開暖色底，沒有以動畫量、AI 介面或新增產品功能替代可用性修正。公開站和工作區仍可有不同視覺表現，但共享閱讀、焦點與主要操作的基本規則。

## 範圍限制

本輪持續使用合成資料、固定示範密碼及記憶體狀態，未加入正式後端、Session、資料庫、MFA、郵件、地理服務或資料移轉。畫面中的權限與身分切換工具不是安全邊界。

本輪沒有新增真實地圖搜尋、活動報名、付款、AI 助理或平台超級管理員，也未以 UI 更新宣稱其他階段完成。[需求基準](13-requirements-baseline.md)及[角色矩陣](14-role-matrix.md)仍是正式業務邊界；後續串接待辦見 [UI／UX 規格](21-ui-ux-spec.md)。
