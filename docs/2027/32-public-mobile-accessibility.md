# 第二階段：公開頁手機與無障礙操作改善

更新：2026-10-15。保持品牌配色、舊版行事曆資訊架構與假資料模式，不新增後端。

## 發現與修正

| 問題 | 修正與使用效果 |
| --- | --- |
| 商家詳情只有模擬 modal，背景仍可取得焦點 | 改用原生 dialog.showModal，背景由瀏覽器阻擋互動；Escape／關閉後回到原觸發按鈕 |
| 對話框開啟時背景捲動、換頁可能殘留捲動鎖定 | 開啟保存原 overflow 並鎖定，關閉或卸載還原 |
| 手機導覽缺少 Escape、窄高視窗按鈕可能出界 | Escape 關閉並回選單按鈕，焦點離開導覽後收合；選單限制高度並可捲動 |
| 行事曆重試後，原按鈕卸載導致焦點遺失 | 僅使用者重試成功後移焦月份標題；初始模擬載入不搶焦點 |
| 月曆／列表按鈕缺少群組語意 | 補 role=group 與可辨識群組名稱，保留 aria-pressed |
| 行事曆導覽按鈕過小、320px篩選列擁擠 | 年度／月份／今天／呈現方式按鈕至少44px，手機篩選改單欄、月份改四欄 |
| 表單焦點與長文字換行不一致 | 補公開表單可見焦點與長文字換行，支援窄螢幕與文字放大 |

月份格保留每週七欄，320px 下日期格約35px寬，不宣稱全部觸控目標達44px。完整日期以可存取名稱呈現，鍵盤仍可用方向鍵、Home／End、Page Up／Down移動。

## 驗證範圍與方法

- 自動瀏覽器涵蓋首頁、地圖、行事曆、社團列表、社團詳情、活動詳情，在320／640px寬檢查無整頁水平溢出。
- 以每個元素原computed字級乘二，驗證實際200%文字放大；不以只調整根rem冒充px字體放大，也不宣稱等同所有瀏覽器縮放模式。
- 手機選單Escape與焦點返回、568×320短螢幕選單捲動。
- 原生對話框模態狀態、程式嘗試聚焦背景被阻擋、Tab不落入背景控制、Escape後回原按鈕與恢復捲動。原生Tab可移向瀏覽器介面，不以body短暫獲焦當成背景控制可互動。
- 行事曆重試成功聚焦月份；初始載入不搶焦點，導覽按鈕尺寸檢查。
- 獨立審查另驗證對話框開啟後換路由，捲動設定還原且焦點回到新頁主要內容。
- 品牌紅 #a72c3b／白底對比6.85:1，次要文字 #6e6668／白底5.58:1；本輪保留配色。只代表所列色組，不代表全站每個狀態已完成對比稽核。

瀏覽器指令：`npm run test:browser:public-accessibility`。已加入Pages部署檢查。
