# 需求基準 v1.0：剩餘規格決策

日期：2026-10-15（Asia/Taipei）。狀態：需求與設計基準完成；程式、實測、正式資料移轉與上線尚未完成。

使用者授權依合理性原則補齊剩餘 To-do。本文件保留先前明確決策，新增內容為本輪採用的預設，後續可提需求變更。發生衝突時，以本文件及目前版階段清單為準；01～12 原有討論及來源保留作追溯，不再表示需要逐題確認。外部資產未取得不等於規格未決；不虛構供應商、授權、銀行驗證或正式站驗證結果。

## B01 範圍與完整流程

- 平台服務扶青社會員與社團，扶輪社籍可同人並存。第一階段：註冊登入、個資、入社、三段式轉社、退社／OB、年度確認、社團與角色管理、歷史公開同意、異動查詢及登入後會員搜尋。
- 第一條流程：自行註冊 → 填個資 → 申請入社 → 該社管理者核准 → 取得社籍及會員被查詢資格 → 授權者維護名冊；地圖資格先建立規則，地圖在階段 3 交付。
- 階段順序固定：1 會員／社團／權限 → 2 活動行事曆與公開社團頁 → 3 公司名錄／地圖 → 4 廣告曝光與優惠兌換 → 5 分批移轉、試用、上線。資料盤點可並行。
- 第一階段不含活動報名、簽到、線上金流、發票、社群登入、LINE／簡訊通知、聊天、原生 App 或銀行證件辨識。帳號復原信為必要系統信；同意請求與審核通知使用站內待辦。
- ROTARACT、ROTARY、JCI、BNI 為穩定類型代碼；第一階段扶青社流程與扶輪社籍模型納入，JCI／BNI 僅保留類型且不啟用寫入。未來體系的組織與上限另以新版本啟用，不套用扶輪規則。

## B02 帳號、登入與復原

- 永久 UUID accountId 關聯一份會員資料；accountCode 自動亂數、英數底線 6～20 字元、不分大小寫、全平台唯一，只可修改一次。舊代號永久保留、不可登入或重新分配。代號預設以英文字母開頭生成，避免與電話識別混淆。
- Email、電話、代號均可搭配密碼登入。Email 去首尾空白並全地址不分大小寫比對，保留原輸入作呈現；不移除加號標記或點號。電話依國碼正規化 E.164，使用成熟電話解析函式庫，國碼選擇不依 IP 猜測；唯一性依正規化值判斷，選填 null 不占值。
- 登入輸入依 Email 格式、電話格式、代號分別解析；衝突格式的自訂代號不得建立。識別不得透過格式歧義登入另一帳號。
- 本人一次只變更電話或 Email，以當次目前密碼驗證；伺服器原子檢查唯一性、更新識別與稽核，成功後舊值立即失去登入用途，其他工作階段撤銷，當前工作階段輪替。輸入正確密碼不免除欄位檢查。通用個資 PATCH 不可繞過此操作。
- 註冊必填姓名、call name、Email、密碼，電話選填；call name 可重複。姓名目前本人可改，未來銀行身分／證件驗證列為停用的可選整合，不在本階段收證件。電話／Email 驗證碼亦列為後續可選功能，不要求本階段提供。
- 密碼 12～128 Unicode 碼點，保留空白、不截斷、不強制組合，允許貼上及密碼管理器。使用維護中的 Argon2id 實作、離線常見弱密碼清單；密碼及衍生可逆內容不得進日誌。登入嘗試每帳號及 IP 限流，初始每 15 分鐘 10 次失敗後短暫冷卻，回應不揭露帳號存在。
- Cookie 型伺服器 Session；Secure、HttpOnly、SameSite=Lax，所有變更有 CSRF 防護。閒置 30 分鐘、絕對 12 小時到期，不預設永久登入。停權與撤權下一次請求即生效，不信任舊 Session 角色快取。
- 忘記密碼：一次性隨機 token，資料庫僅保存雜湊；30 分鐘、重送使舊 token 失效、成功後撤銷全部 Session。請求回覆統一，單帳號每 60 秒一次、每小時最多 5 次，另有 IP 限流；重設失敗不變更密碼。
- 無法收信採人工復原案件：記錄原 accountId、申請、新信箱、證據、處理人、結果；由本人提供既有社籍／帳號可核對資訊並由所屬社團具名管理者佐證，再由平台帳號支援角色核對，不能僅靠新 Email 或姓名。無獨立證據則不核准。無社籍帳號可用既有工作階段／復原紀錄等獨立持有證據；無法核實則保持待補件。核准後以新信箱一次性連結確認持有權、強制重設密碼、撤銷舊 Session，不直接給臨時明文密碼。敏感證據限制支援案件存取，結案 30 日刪除附件。

## B03 角色、動作與資料範圍

具體矩陣見 [角色矩陣](14-role-matrix.md)。所有權限在伺服器逐請求驗證；個人、社籍、社團及地區範圍分開，列表／詳情／匯出／附件一致。

- 個人社長、秘書、一般社團管理者依任期授權，任期起日可立即或未來生效，最晚該年度 6/30。7/1 職務交接；一般管理者由新任社長重新分配，前任不保留職務權。多社團角色分開選範圍，不能混用。
- 社長、秘書、社團管理帳號可指定後任與該社角色；一般管理者不可。無人交接由轄內地區管理者協助。地區管理角色由平台權限管理員授予、限指定地區與最晚年度結束，續任另授權；平台特權不可由地區／社團自授。
- 社團管理帳號是備援、綁一社團，不是會員身分；初次發放僅給現任社長保管，交接強制改密碼、撤銷舊 Session，復原由地區確認後交帳號支援處理。共享帳號只可追查操作帳號，不宣稱可識別實際使用人。無現任個人管理者時保留備援與地區復原路徑。
- 平台角色分拆為權限管理員、帳號支援、內容／曝光管理員、維運人員、特定 admin。維運僅部署、健康、遮罩日誌，不自動讀個資；一般平台角色不互相繼承。
- 「較高權限管理者」本輪定義為具額外 history:moderate 授權的社長、秘書、地區管理者或平台內容管理員；不得因稱謂自動取得。scope 限自己社團／地區／明確內容範圍。一般管理者／備援不預設具有此授權。
- admin 為獨立具名 history:override 授權，只有平台權限管理員可給，需到期日，最長 90 日；本人不可核准自身授權。每次例外公開需目前密碼、理由及稽核，僅略過該筆歷史的本人同意，不略過輸出白名單或其他個資限制。
- 平台權限管理員及特定 admin 強制 TOTP MFA；初始帳號以受控 bootstrap 設置，不公開註冊管理帳號。其他管理角色可選啟用 TOTP。遺失 MFA 走人工復原，不建共用超級密碼。
- 停權帳號不得登入及寫入、其私有資料不因停權公開；停止其個人商家免費曝光，獨立付費廣告是否暫停由曝光管理員按內容／帳號事件明確處理並記理由，不能用停權暗改付費期限。

## B04 組織、欄位與停用

- 扶輪體系管理地區與扶輪地區一對一；社團在同一時間只屬一個地區，地區代碼唯一。不同社團名稱可重複，以地區及永久 ID 區分，禁止以名稱作關聯。
- 地區欄位：id、code(2～32)、name(1～100)、status。社團：id、name(1～100)、clubTypeCode、districtId 必填；社徽、簡介(最多 5000)、Email、網站與社群連結選填。
- 社長／秘書／備援可改名稱與社徽，一般管理者可改介紹及聯絡；類型與地區由轄內地區管理者處理。已有社籍的類型不可直接改，採更正案件重新映射、驗證既有社籍上限並留歷史；跨區由來源與目標地區管理者分別核准，單次交易調整範圍，不將舊管理權帶往新地區。
- 社徽／頭像僅 PNG、JPEG、WebP，2 MiB、最大 4096×4096，驗證內容並重編碼、移除 metadata，拒絕 SVG／偽裝格式。無圖顯示文字替代，不套用他人頭像。檔案有所有者及存取範圍。
- 社團名稱、類型、地區、社徽、簡介預設公開；社團 Email、網站與社群連結預設不勾選，管理者可逐項開啟。所有 URL 僅 HTTP(S)，不接受腳本或任意重導向；介紹文字採安全純文字／受控格式，不直接插 HTML。
- 轄內地區管理者可停用／恢復社團，須原因與紀錄；社團管理者可提出案件。停用保留資料，停止新入社與新增活動；未完成入社或涉及該社的轉社申請標為 terminated（club_disabled），原社籍保留。恢復不自動重啟申請，須重新提出。
- 社團停用：已結束活動保留可公開歷史，未開始或進行中的活動撤下公開，管理端保留。取消或轉主辦須理由；轉至其他社團需該社管理者同意。恢復社團不自動重新發布活動。

## B05 入社、轉社與期間

- 同類型一次一筆 pending 入社申請；伺服器及資料庫保證上限，核准時再查有效社籍。申請只供本人與該社審核者看；審核可見姓名、call name、說明，私人電話／Email 遵守本人隱私。
- 入社申請 pending → approved／rejected／withdrawn／expired／terminated；30 日無結果自動 expired。拒絕必填原因，本人可改資料後重新申請；同社拒絕後 24 小時內不可重送，每會員每天最多 5 筆。保留原案件，新送另建。
- 審核者填／確認實際入社日期，預設核准日，只能為今日或過去、不得晚於結束日或重疊既有同類型期間；歷史未知日期保留未知，不猜造。回溯日期不產生過去的登入或曝光權。衝突交地區管理者更正案件處理。
- 會員／類型同時最多一個有效扶青社籍及一個有效扶輪社籍。Membership 狀態 active、ended、void；endReason 為 transferred、resigned、ob、correction。OB 是畢業結束原因，不等同 active；年度確認為獨立狀態 confirmed／grace／unconfirmed。
- 本輪不加入停籍、榮譽社籍、未來自動生效等額外狀態；需要時走需求變更，不以模糊狀態繞過上限。
- 日期期間 [startsOn, endsOn)，同日轉社原社籍 endsOn = 新社籍 startsOn。生效時間另存 executedAt；日期及時間以 Asia/Taipei 判定業務日，UTC 存瞬間。
- 轉社本人申請 → 原社核准＋目標社核准 → ready_for_member → 本人最終確認執行 → completed。等待期間原社籍保持；任何一社任一授權審核者可代表該社同意，並不代替另一社。雙方核准不自動生效。
- 任一方拒絕即 rejected 且須原因；本人完成前可 withdrawn；原申請 30 日逾期或 ready 後 7 日未確認（取較早者）expired。拒絕／撤回不改社籍。申請內容或目標變更須另起申請。
- 最終執行再次驗證本人、兩社啟用、兩邊有效授權、核准版本及原社籍未變；失效標 needs_reapproval，回有效方重審，不悄悄執行。以版本與交易競爭，撤回與完成先成功者成立，後者 409。不得留下半筆轉社。
- 本人退社／OB 申請由該社管理者確認；管理者可直接辦理但須原因；完成時結束社籍並保留歷史。日期不能偽造或破壞已核准後續期間，錯誤以更正案件處理，不覆寫歷史。

## B06 年度、查詢與隱私

- 扶輪年度 7/1～隔年 6/30。7/1 台北零時啟用新任期；前年度正常且仍 active 社員進 grace，7 月保留曝光；8/1 尚未確認改 unconfirmed 並撤免費曝光，已退社／OB 不因寬限復活。
- 年度確認由社長、秘書、一般管理者、備援操作自己社團；補確認後立即恢復免費資格。排程可重跑且有補跑機制，資格查詢直接檢查日期，不靠排程是否成功決定到期。
- 未登入僅能查公開地圖、公開活動、公開社團；會員查詢及優惠兌換須登入。正常名冊只列至少一筆正常／寬限社籍者；勾選特殊篩選可查已退出／OB／待確認者，但不列從未核准入社的註冊者。本人與授權管理者可看自己的待辦。
- 會員電話預設 hidden、Email 預設 visible（僅登入會員查詢），本人 checkbox 修改；姓名不在地圖展示；登入會員名冊／詳情可呈現姓名、call name、社團及狀態。列表不放電話／Email，詳情按隱私呈現。私人聯絡方式隱藏時，社團管理者也不因角色自動看到；個別支援案件另有稽核。
- 本人可修改姓名、call name、頭像、聯絡方式、隱私；不得改角色、accountId 或社籍。管理者只管理社籍／年度，姓名或聯絡錯誤由本人更正，支援例外限案件。地區管理者不因查看名冊取得無限制個資修改權。
- 會員查詢篩選姓名／call name、地區、社團、類型、年度狀態；搜尋只匹配可見欄位，不能利用隱藏電話或 Email 篩選判斷身分。最小分頁 20、上限 100，禁止匿名會員搜尋與批量爬取入口。

## B07 歷史公開、備查與稽核

- 新建及移轉歷史預設 hidden。公開欄位僅類型、社團名稱快照、所屬地區快照、已核實起迄期間與狀態；內部備註、私人聯絡、移轉原始值、原因與證據不公開。本人可逐筆公開或隱藏；匿名 API 不提供整體會員經歷搜尋入口。
- 獲 history:moderate 管理者可範圍內隱藏／提出公開請求，不能代同意；pending 不等於 public。彈窗顯示請求者、內容、公開對象與欄位，按同意／拒絕／稍後，關閉不當成同意。
- 同意請求 7 日到期，同筆同版本只一筆 pending，拒絕／過期後 7 日冷卻；不外寄提醒，站內待辦可見。請求綁本人、資料及公開版本，內容／對象變更、撤權、隱藏或 override 時失效。
- 修改已公開內容、增加欄位或擴大對象必須同交易退回 hidden，取得新同意或本人重新確認後再公開；admin 新版本例外也需明確執行與記理由。隱藏及公開變更須同步更新所有系統入口，不用延遲快取假裝完成。
- 原社團僅能備查本社那段姓名快照、call name、社籍期間／類型／結束原因與異動；不可見轉社後新聯絡方式、新社資料、其他社籍。預設結束後保留 5 年，期滿去識別化，歷史本人可保留基本經歷；遇法定保留或爭議案件暫停刪除並記理由。
- 稽核記錄操作者、時間、來源類型、目標、動作、理由與受控差異；聯絡值加密、日誌遮罩，禁止密碼／token／驗證碼。本人看自身變更，不可看到他人資料或支援證據。權限管理員看授權事件，維運只看遮罩技術事件。
- 稽核與申請案件保留 5 年，系統日誌 90 日，復原證據結案 30 日；刪除案件 30 日內處理、法定／爭議保留另標。申請撤回不刪除已發生事件。這是產品預設，可因實際營運法域以需求變更調整，不宣稱已完成法律審查。
- 第一階段不開一般會員名冊批量匯出；地區匯出需獨立 export:members 授權、目前密碼、理由，僅管理欄位與已允許的聯絡欄位，記錄篩選與下載人，產檔 24 小時刪除。

## B08 UI 與前端

- React + TypeScript + Vite，Tailwind CSS；Metronic Tailwind 的 React 版型作參考，採側欄＋頂部範圍列、白卡片、淺灰底。未取得模板前用自有元件及樣式，不下載未授權商用資產；取得模板時依相容矩陣鎖版本，不憑文件連結宣稱已擁有授權。
- 品牌沿用舊版名稱與紅色系；初始 token：brand #C8102E、background #F5F7FA、surface #FFFFFF、text #182230、muted #667085，紅色僅強調操作，文字對比不靠品牌色。此為可變更初始色票，不宣稱精確取自舊版。繁中字體 Noto Sans TC，系統字體 fallback，可自託管字體。
- 手機 360px 以上、平板 768px、桌機 1280px；小於 1024px 側欄抽屜，名冊改卡片，不要求水平滾動操作主要功能。桌機預設 20 筆，頁面記住安全篩選，不把私有資料寫 URL。
- 畫面：登入／註冊／復原、會員搜尋、本人資料、會員詳情（基本／社籍／歷史／異動）、入社待辦、三段轉社待辦、社團資料／名冊／年度確認、角色與任期、本人公開同意、平台支援案件。功能依角色顯示，伺服器再驗權。
- 狀態具備 loading、empty、field-error、401、403／404、409 衝突、429 與服務失敗；保留未送出內容但不保存密碼，離頁有未存提醒，鍵盤可完成流程。目標 WCAG 2.2 AA，色違廣告同時有「廣告」文字。
- 前端 Node.js 24 LTS、npm、React 19、TypeScript 5、Vite 7、Tailwind 4 為初始相容版本線，建置時鎖定當時受維護的相容修補版；Metronic 若不相容以獨立自有元件維持此基準，不強行混入 Bootstrap JS。

## B09 後端與 API 基礎

- 後端採 Java 21 LTS、Spring Boot 3.5、Spring Security、PostgreSQL 17、Flyway；單體模組化 AUTH／ORG／MEM，依接口分模組，不先拆微服務。選型承接舊 Java 經驗但不重用舊密碼機制；依賴鎖修補版並做相容驗證，未宣稱已安裝。
- UUID、UTC timestamptz、IANA 時區；JSON REST `/api/v1`，OpenAPI 3.1。所有更新有 version、範圍、欄位白名單，回應不序列化 Entity。交易內做社籍唯一、申請唯一、一次修改與 token 消耗。
- 契約錯誤 400/401/403/404/409/429/5xx，一致不存在／防枚舉；含 code、message、fieldErrors、requestId，不含敏感堆疊。409 不覆寫他人更新；關鍵建立／執行採 Idempotency-Key，同帳號同路徑保留 24 小時，同 key 不同內容 409。
- 本地 Docker Compose PostgreSQL、Mailpit 模擬信箱；正式使用 SMTP adapter（587 STARTTLS／465 TLS）、設定式憑證、outbox＋有限重試（最多 5 次指數退避），寄信失敗可觀察且不假回已寄達。供應商以可替換配置接入，不預先採購服務。
- 檔案採 S3 相容 adapter，本地檔案測試替身；私人檔案短效簽名連結，依 ownership 驗權。公開衍生圖片與私人原檔分開。

## B10 活動與公開社團頁（階段 2）

- 社團四種管理身分可維護該社活動，社長／秘書／備援可發布，一般管理者草稿交發布者；地區管理者發布自己地區活動，不跨區。各活動主辦 ID 必填。
- draft → published → cancelled／archived，visibility public／members／club。公開取消保留原因與「已取消」標示；私有活動永不出現在匿名 API。取消不可再當成原活動復活，複製新草稿。
- 活動標題 1～200、說明最多 10000、地點 300，開始／結束必填且終點較晚；預設 Asia/Taipei，可選 IANA 時區；時間型存 UTC、全天存 [startDate,endDateExclusive)。跨日／夏令時間／區間重疊查詢納入驗收。
- 公開首頁採搜尋與社團卡片，不保留必要泡泡動畫，提供行事曆／地圖導覽；已公開社團與公司頁可 SEO，會員頁 noindex 且登入保護。停用社團撤公開社團入口，歷史活動仍按 B04 處理。

## B11 公司、地圖與廣告（階段 3～4）

- 會員維護自己的公司關聯，一公司可關聯多人；建立者為 owner，其邀請其他維護者需對方接受；共享公司不讓會員讀到其他人的私人資料。社團／地區管理權不自動取得公司修改權，平台內容管理員可審核與暫停違規內容並記原因。
- 公司必填名稱(1～200)、產業（受控多選）、至少一項營業聯絡方式；電話、Email、網站、營業地址獨立填寫，各可勾選公開，至少一項聯絡公開才上架。電話／Email 不帶入會員私人值。地圖需有效座標及位置公開同意，未提供地址可人工提供營業位置，但不得編造定位。
- 【2026-10-15需求變更】公司改為登入帳號自行發布，取代前置送審；首次發布一次72小時暫時曝光，不能因重新登入、編輯或再次發布延長。期滿須有當年度有效社籍免費資格或有效廣告，否則隱藏公開名錄／地圖但保留資料。平台保留事後退回／暫停；公開仍為白名單，不顯示本人姓名。詳見[三日曝光與社友確認](34-business-exposure-and-community-confirmation.md)。
- 六位不同有效社友確認商家存在後顯示「社友已確認」，建立者與已接受維護者不計、每帳號一次可撤回、確認一年有效、重大名稱／地址／座標異動重新累計；標章不授予曝光資格，不代表合法性、品質或交易保證。
- 任一已接受公司關聯會員具當年度 confirmed／7 月 grace 且 active 社籍、社團啟用，可提供免費資格；同一公司只顯示一標記，可列多個符合資格的 call name／社團。沒有免費資格時，具有效付費廣告也可曝光。付費不賦予社籍或登入管理權；公司未發布／已被暫停／未同意位置／無座標時付費也不繞過。
- 預設 Google Maps JavaScript，使用限制來源與額度的公開瀏覽器 key；不啟用自動 geocoding 或定位，先以人工確認座標，減少意外成本。地圖不可用顯示等價公司列表；切換供應商不改公司資料模型。API 先驗資格、公開欄位再按 bounds／產業篩選，不能從聚合洩漏被隱藏公司。
- 當年度正常社籍免費；非當年度社友廣告按公司申請，平台曝光管理員設定台北日期 startsOn，endsOn = startsOn + 1 calendar year（不含迄日，2/29 次年取 2/28）。未續費到期撤曝光但保留資料。獨立付費不因年度 unconfirmed 失效。
- 廣告保留社團圖標色違＋「廣告」。有付費且有效時仍以廣告標記，即使後來取得免費資格；不自動退款或延長。續期有未到期廣告時 startsOn 預設原 endsOn，否則由管理者設定；禁止重複重疊權益。
- 收款先人工對帳，不接線上支付。新廣告申請與 PaymentRecord、ExposureGrant 分開；只有帳務管理員核對證明後曝光管理員可啟用。報價以可配置方案、金額與幣別填入訂單快照，不編造固定價格，不允許零價意外啟用；未設方案則關閉加購入口。
- 付款狀態 pending／confirmed／void，作廢／更正須理由，重送冪等；實收／退款用追加調整紀錄，不覆寫財務事件。付費紀錄非公開。舊 Pay 資料語意不明者保留 legacy 記錄，不推導新付款或曝光。
- 優惠兌換在階段 4，商家 owner 建優惠草稿、設定效期／名額／每帳號上限、內容管理員核准；登入且當年度正常社籍者可領一次性兌換碼，商家 owner 驗證未用且未過期後原子核銷。無線上金流、不作支付憑證；作廢、重送、超額、匿名與跨公司核銷均測試。

## B12 移轉、保留與上線

- 允許舊會員資料先無帳號，內部 memberId 與來源 ID 保持映射，預設不公開／不曝光。本人註冊後提出認領，社團管理者核對既有紀錄，平台支援確認帳號持有證據後綁定；不以同名／相同電話單一條件自動合併。衝突隔離、同類型社籍上限先清理再認領，memberId 不變。
- 批次：地區／社團／字典 → 帳號與會員／社籍 → 活動 → 公司／關聯 → 可核實廣告與財務。來源 profile、schema、筆數、日期精度與核實結果進 manifest，sourceSystem＋sourceRecordId 唯一，重跑不重複。
- 只取去識別化樣本先試轉，不搬舊密碼／登入憑證；無法對帳、孤兒關聯、未知社籍類型、同人衝突進隔離清單，業務擁有人修正後重跑。移轉歷史 hidden，舊公開旗標不當新同意。
- 試轉驗收筆數／關聯／金額（僅可證實者）／資格／隱私；上線前完整備份與還原演練、預定唯讀凍結窗口、最後增量、差異對帳、切換與可回退版本。對帳不符即停止切換，不能讓新舊系統同時接受寫入後直接回滾。
- 執行環境規劃 staging／production 分開，容器化前端靜態資產與後端，TLS 反向代理、PostgreSQL 私網、SMTP／S3 設定式接入；主機供應商不綁死。每日備份、切換前快照，預設 RPO 24 小時、RTO 4 小時，實際演練驗證後才對外承諾。
- CI 規劃 frontend typecheck／lint／unit／build、backend unit／PostgreSQL integration、OpenAPI schema、權限 E2E，合成資料與祕密分離；部署要有明確版本與回退，不把規劃當實測。

## B13 品質與交付界線

- 驗收必含跨社／跨區直接 API 拒絕、角色到期、1 次代號變更競爭、Email／電話唯一、憑證單次使用、單項識別變更、三段轉社與撤回競爭、年度 7/1／8/1 邊界、免費／付費曝光、同意重放與撤回、私有快取失效、備份還原。
- 以 1 萬合成會員、100 社團、100 同時使用者為首輪負載樣本；列表 p95 < 1 秒、寫入 < 2 秒（不含外部寄信／地圖）為初始驗收目標，不宣稱 SLA；超標先測瓶頸與索引再擴架構。
- UI 主流程以手機 360px、桌機、鍵盤驗收；公開地圖失敗可列表替代；信件 adapter 失敗可重試並有案件狀態，不假回成功。
- 第一階段欄位與端點範圍見 [開發契約清單](15-phase1-contract.md)。正式 OpenAPI、可點擊雛形、程式、CI 與驗收是實際開發交付，保持未完成，不以規格決策取代。
- 尚需實際取得的資產：Metronic 可用授權／模板（沒有則自有元件）、舊品牌原始檔（未有則用初始 token）、正式 SMTP／地圖 key／主機設定、經授權移轉來源與營運初始管理者。此類屬供應／設定工作，不能由推理假裝完成。
- 需求變更記錄 CR 編號、原因、舊／新行為、受影響角色／資料／API／驗收與移轉；先更新本基準與階段清單，再實作。仍保留使用者先前的正式資料切換與上線授權邊界。
