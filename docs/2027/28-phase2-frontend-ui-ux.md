# 第二階段前端 UI／UX 初版

最新調整：[公開行事曆沿用舊版資訊架構，以 React 重做](29-legacy-calendar-react.md)。

更新：2026-10-15。依使用者指示，暫停新增後端，先交付活動、共同行事曆與社團公開頁。全部使用合成資料，不代表活動後端、正式登入授權或SEO已完成。

本輪使用預設展示模式，執行`npm run dev`即可查看，不需啟動API。請勿設定`VITE_API_MODE=live`查看活動管理示範；既有live模式維持帳號／入社的串接範圍。

## 畫面與入口

| 畫面 | Hash路徑 | 使用情境 |
| --- | --- | --- |
| 公開首頁 | `/` 或 `#/` | 維持React起始入口，增加公開社團搜尋及活動摘要 |
| 探索社團 | `#/clubs` | 關鍵字／地區搜尋、社團卡片及無圖替代視覺 |
| 社團公開頁 | `#/club?id=taipei` | 簡介、地區、已勾公開聯絡方式及公開活動 |
| 共同行事曆 | `#/calendar` | 月曆／列表、月份切換、關鍵字／地區／主辦社團篩選 |
| 活動詳情 | `#/event?id=city-walk` | 日期、時區、主辦、地點、說明及取消原因；可直接開啟及重新整理 |
| 活動管理示範 | `#/demo?view=events` | 草稿、預覽、發布確認、取消、封存、複製及版本衝突示範 |
| 會員活動閱讀 | 工作區「活動與行事曆」，體驗身分選會員 | 唯讀公開、會員限定與本社限定活動，展開詳情；沒有維護控件 |

預設公開首頁不載入管理App。公共詳情切換同類型不同ID會更新內容；未知／私有／未公開／已撤下內容顯示一致的不存在頁，不在DOM殘留私人活動。GitHub Pages使用Hash路由，不能把這些詳情頁當成已完成搜尋引擎索引。

## 視覺與操作

延續Rotaract紅色、暖白背景、清楚的大標題、社團卡片與留白。管理區維持現有側欄，新增「活動與交流」分組；表單以主辦、內容、時間及預覽分區，狀態用文字及色彩同時呈現。控制項以44px觸控高度為原則，手機優先用活動列表。

- 日曆固定以Asia/Taipei排列日期，活動詳情保留原設IANA時區。跨日活動會出現在所有重疊日期。
- 活動列表按開始時間排序。沒有符合資料時，可清除篩選；沒有當月活動時可回示範月份。
- 時間型活動用當地時間輸入並轉UTC；DST跳時不存在則拒絕，回撥重複時由使用者選較早／較晚時段。
- 全天採`[開始日期, 結束日期)`，表單明確提示結束日不含當天，不把UTC午夜當作所有時區的全天邊界。
- 草稿未儲存時，換頁、返回首頁或切換身分需確認；取消離開會保留URL及輸入。無效日期預覽只顯示錯誤，不讓整頁崩潰。
- 模擬其他人更新後，以版本不符拒絕儲存，保留目前文字；重新載入需確認捨棄草稿。

## 顯示範圍與生命週期

- 社長／秘書／備援可發布自己社團活動；一般社團管理者只能維護草稿，畫面提示交由發布者處理，不另加審核狀態。
- 地區管理者維護自己地區主辦的活動，不因此取得各社團活動的修改權。
- 訪客只看公開且已發布／已取消活動。會員另外可讀會員限定及本社限定的已發布／已取消活動，看不到他社專屬內容或草稿。
- 取消必填原因、保留原內容，不能重新發布原活動；可複製成另一份新草稿。
- 本輪封存採「公開行事曆下架、管理端保留紀錄」，不能直接復活；私人閱讀也不列封存內容。
- 同一次瀏覽共用記憶體狀態，因此管理端發布、取消或封存會同步反映公開頁。重新整理會重設，沒有跨裝置或持久化資料。
- 停用社團不出現在社團列表／詳情；停用前已結束的公開活動保留歷史，停用後才結束的活動不因時間經過而重新曝光。社團聯絡資訊按各自公開旗標投影，隱藏值不放入公開元件。

上述都是前端模型與UI模擬，不是正式資源授權。

### 本輪發現與修正

- 全天缺少結束日期時預覽造成整頁錯誤：預覽先驗欄位，再格式化顯示。
- 同一活動詳情路由只換ID卻顯示舊內容：公共畫面依完整hash更新，保留原有草稿離頁保護。
- 停用後原未來活動隨時間經過重新曝光：以停用瞬間檢查活動何時結束，不只比較現在時間。
- 一般會員沒有私人活動閱讀入口：補上唯讀列表與詳情，分開可讀範圍和管理範圍。
- 活動類型由標題猜測、日期列表未排序：移除猜測分類，改用明確的日期、關鍵字與主辦篩選並按時間排序。
- 取消與封存文案不一致：取消保留公告；封存撤公開、管理保留，不能原筆復活。
