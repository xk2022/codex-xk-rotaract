# 本人帳號與隱私 API 串接

更新：2026-10-15。延續[核心入社流程](26-core-api-integration.md)，本輪新增本人資料、聯絡方式、代號與聯絡隱私的本地串接。

## 範圍與規則

| 操作 | API | 規則 |
| --- | --- | --- |
| 姓名、call name | `PATCH /me/profile` | 本人修改，使用會員版本；不走身分驗證，拒絕管理欄位 |
| 電話／Email隱私 | `PATCH /me/privacy` | 本人checkbox；電話預設隱藏、Email預設對登入查詢者開啟，隱藏欄位從投影省略 |
| 單項電話或Email變更 | `POST /me/contact-changes` | 目前密碼、帳號版本及冪等key；檢查正規化唯一性，舊值立即不能登入，撤其他Session並輪替當前Session |
| 帳號代號修改一次 | `POST /me/account-code-changes` | 目前密碼、帳號版本及冪等key；不改永久UUID，舊代號不可登入且永久保留 |

姓名與call name可自行調整；銀行／證件身分驗證、電話與Email驗證碼仍是後續可選整合，本輪不啟用。會員電話與Email隱私和公司公開聯絡方式是不同資料，不互相帶入。

目前密碼錯誤依既定契約回401，**不代表Session已過期，也不撤銷仍有效的Session**。畫面保留非密碼草稿，清除密碼，顯示可修正錯誤。版本衝突回409，不自動覆蓋新版資料；使用者先確認保留的草稿，再明確重新讀取。

頭像上傳與資產服務仍未實作；可清除頭像，但不能藉由任意asset UUID綁定他人資產。

## 操作模式

啟動方式沿用[後端說明](../../backend/README.md)與[前端說明](../../frontend/README.md)。只有 `VITE_API_MODE=live` 啟用本輪真實串接；公開根網址仍為首頁，GitHub Pages預設仍使用合成資料。

CSRF、Session及密碼不存localStorage。聯絡方式成功變更後採伺服器回傳的當前Me與CSRF，避免繼續使用舊Token。重送不重複變更或再次消耗修改次數，敏感回放仍加密且按目前會話及可見範圍投影。

### 本輪修正

- 錯誤碼使用既定`AUTHENTICATION_FAILED`，未擴張OpenAPI列舉；畫面透過Me辨識錯密碼與真Session過期。
- 聯絡方式變更的Cookie在交易提交成功後才送出，避免回滾卻使原登入失效；輪替保留原登入時間，不能藉由反覆變更延長12小時絕對期限。
- 登入／聯絡變更以帳號鎖及Session重新確認處理競爭，舊識別或已撤銷會話不能建立新Session。
- 冪等回放重新取得目前Me，不回傳過期CSRF或舊聯絡／角色資訊；代號次數不被重複消耗。
- 目前密碼按Unicode碼點驗證，不受HTML UTF-16長度截斷；失敗清除密碼並保留其他草稿。
- 送出期間同步鎖住父層導覽與登出，避免Session輪替回應與離頁操作競爭。
- 瀏覽器測試不再對成功204強行讀取不存在的response body。

目前已有17個operation；其餘42個仍未實作。此計數不表示頭像資產等依賴已完成。
