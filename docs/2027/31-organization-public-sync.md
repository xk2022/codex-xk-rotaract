# 第二階段：社團停用／恢復與公開頁同步

更新：2026-10-15。沿用需求基準 B04，不新增後端；將既有地區社團管理與公開社團／活動的記憶體假資料接成同一操作流程。

## 操作入口與規則

地區管理示範：`#/demo?view=district`，體驗身分選「地區管理者」。填寫操作原因，檢查摘要後確認停用或恢復轄內社團。

- 停用保留社團、社員與活動資料，公開社團列表與詳情隱藏；停止新入社與新增活動。
- 既有未完成入社／轉社申請沿第一階段邏輯終止，原社籍保留；恢復後不自動重啟。
- 停用當下已結束的公開活動保留可公開歷史；未開始或進行中的活動撤下，管理端保留。
- 恢復社團後重新開放新申請與公開社團頁，但被撤活動不自動重新公開。需要重新發布時，複製成新草稿並由有發布權者發布。
- 停用時間於成功操作時記錄，不使用固定業務示範日，也不依每次查詢重新決定撤下對象。
- 操作仍經過既有組織權限與轄區驗證；公開資料仍套用可見性投影。
- 重設示範資料一併重設社團／活動；一般停用、恢復則保留資料與撤下狀態。

## 驗收清單

- [x] 管理端停用後，同次瀏覽的公開社團頁／列表同步隱藏。
- [x] 已結束活動保留，進行中與未開始活動撤下；地區主辦活動不受旗下單社停用影響。
- [x] 恢復後社團頁可見，被撤活動仍不可見。
- [x] 無權限、跨區與失敗命令不產生部分更新。
- [x] 初始公開聯絡設定不被另一份管理假資料覆寫。
- [x] 版本衝突、複製新草稿與重設行為正確。
- [x] 單元、正式建置、瀏覽器驗收與獨立審查。

## 使用限制

僅同一次瀏覽中的合成資料同步，重新整理重設，沒有資料庫、正式API權限、排程、通知或跨裝置同步。第一階段商家地圖仍是獨立展示資料，不能將其視為已與此組織生命週期完整串接；免費／付費曝光的正式資格與地圖資料同步留到第三、四階段。
